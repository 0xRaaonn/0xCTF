# 🧩 Plug & Pray (250 pts)

> 🔌 “Free WiFi Booster”… what could go wrong?

---

## 📌 Challenge Description

At Narita Airport, you found a USB dongle labeled “Free Airport WiFi Booster” near the business lounge. Being curious, you plugged it into your laptop. Your antivirus didn't flag anything, but you're suspicious. You managed to capture the network traffic generated by this dongle using Wireshark.

Analyze the packet capture file (or use the screenshot of the packet capture file) to identify what this device is doing and extract the flag hidden in the network traffic.

---

## 🧠 Initial Thoughts

This is a **network forensics + malware traffic analysis** challenge:

- DNS queries → possible hidden data  
- HTTP traffic → behavior clues  
- C2 communication → attack classification  

Flag format:

```
LIC{[deviceID][attack method][attack_behaviour]_detected}
```

---

## 🔍 Analysis & Approach

---

### 🧩 Step 1: Identify Device ID (DNS Analysis)

From DNS queries:

```
malware.tracking.48756e744f6e6965.example.com
exfiltrate.48756e744f6e6965.beacon.com
```

👉 Repeating hex string:

```
48756e744f6e6965
```

Convert **Hex → ASCII**:

```
48 75 6e 74 4f 6e 69 65 → HuntOnie
```

👉 Device ID:
```
HuntOnie
```

---

### 🧩 Step 2: Identify Attack Method (Traffic Behavior)

From the traffic:

- HTTP request includes:
  ```
  infected=true
  ```
- Response decodes to:
  ```
  send home log files
  ```

👉 Indicates:
- Data is being sent out  
- Communication with external server  
- Presence of **Command & Control (C2)** infrastructure  

👉 Attack method:
```
c2
```

---

### 🧩 Step 3: Identify Attack Behaviour

From DNS and traffic patterns:

```
exfiltrate....beacon.com
```

👉 Keyword:
```
beacon
```

This reflects:
- Periodic callback behavior  
- Malware beaconing to C2  

---

## 🧾 Final Reconstruction

- Device ID → `HuntOnie`  
- Attack Method → `c2`  
- Behaviour → `beacon`

## 📚 Key Takeaways

- DNS can carry encoded identifiers  
- HTTP reveals attacker intent  
- Malware often uses:
  - **C2 communication**
  - **Beaconing behavior**

---

## ⚡ Pro Tips

When analyzing PCAPs:

1. Extract and decode unusual DNS strings  
2. Inspect HTTP payloads carefully  
3. Look for:
   - Beacon intervals  
   - Suspicious domains  
   - Exfiltration patterns

This challenge reinforces:

> **Malware rarely hides everything — it leaks through network behavior**

By correlating DNS, HTTP, and patterns, you can reconstruct the full attack.
